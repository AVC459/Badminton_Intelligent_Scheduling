高校羽毛球赛事智能抽签与编排系统研究
  文晨尧　高　科　黄翊轩　刘阳阳　龙思怡
  咸阳师范学院，陕西咸阳，712000
  摘要：高校羽毛球比赛人工编排时常常碰到几个麻烦：种子分得不匀，同一个单位的选手过早相遇，结果也不便核对；本文针对这些问题做了一套智能系统，既能用在赛前编排上，也能用在赛中记分上。本文把竞赛规则里种子定位、同单位回避的要求整理成计算机能处理的条件；抽签时让种子按蛇形落位先排开，再让非种子按“同单位尽量分散”的目标依次落位，首轮如果还有同单位对阵，就建冲突图把冲突找出来，用局部搜索换位修到消除为止；对阵表按逐轮配对生成，人数是奇数时轮空一人，另外还算出一份公平性得分和风险提示。实测下来，一百多人的名单几秒钟就能排完，轮空、弃权和名次计算都能正确处理，编排过程也有留痕可以复现。
  关键词：羽毛球赛事；智能抽签；赛程编排；局部搜索；微信小程序

引言
　　羽毛球在我国高校里是开展得最广的体育项目之一，院系赛、校运会这类比赛每年都要办很多次，可是组织工作一直靠人工，组织者得在纸签到筒里抽签，再凭经验把几十场比赛塞进有限的场地和时间里。人一多，毛病就露出来了；一是公平性不好证明，种子有没有分匀、同学院选手会不会第一轮就碰上，只能听组织者口头说；二是效率低，32 人的淘汰赛手工排表一般要花一到两个小时，有人弃权或改期，整张表都得重排；三是赛程容易冲突，同一名选手被同时排在两块场地上、上一轮没打完下一轮就开始了，这类错误很难避免。
　　在竞赛编排的规范化方面，学界积累已经比较多；文献[2]给出了单淘汰赛里种子和轮空分批定位的计算公式；文献[3]专门讨论了“死签”，也就是先定好种子位置、再抽非种子选手时可能出现同队选手分不开的情况，并提出用调整种子位置的办法避免；文献[6]、[7]从定位抽签控制技术和种子合理定位角度给出了具体方法。这些研究把规则讲清楚了，可规则最后还是要靠人执行，里面的组合约束并没有变成能直接运行的计算过程。本文要做的就是把这些规则编成算法，做出一个完整的系统，把赛事创建、智能抽签、赛程排布、逐场记分、名次公示串起来。

1　系统总体设计

1.1　架构设计
　　系统分成客户端和服务端两部分。客户端是用 uni-app 和 Vue 2 做的微信小程序，负责现场报名、触发抽签、逐局记分和查询赛程这些跟用户打交道的活；服务端用 Spring Boot 搭起来，算法计算和数据保存都放在这一边；两边通过 HTTP 接口通信。
　　服务端按职责分成五层；接口层管参数校验和统一响应包装；业务层管事务边界和状态流转；算法层纯粹做计算，不依赖数据库也不依赖框架，只收选手集合和配置参数；持久层用 MyBatis-Plus 读写数据；实体层和数据库表一个对一个。算法层单独拿出来之后，各种赛制算法都能不要数据库单独测试，以后换算法，业务代码也不用改。

1.2　数据模型
　　数据用 MySQL 8 存，一共设计了 7 张业务表，表名前缀用 sys_local_ 和 biz_local_ 把账号表和业务表分开。赛事是根实体，其他表都靠 tournament_id 挂在它下面。

2　核心算法设计

2.1　淘汰赛智能抽签算法
　　单淘汰赛最要紧的是人和位置怎么对上，算法分四步做一次抽签。
　　第一步是先定一条落位顺序，长度直接取参赛人数，不把人数撑到 2 的整数次幂，也不预留空签位；这样后面每轮都能把当时剩下的人两两配对，不会多出一堆没人打的空签。
　　第二步是种子蛇形落位。种子不参加随机抽签，按固定路线落位；算法用的是蛇形落位，最高顺位放首位，第二顺位放对称的末位，剩下的种子用递推方式交替填向各段，这样 1、2 号种子分处两端，1~4 号分处四段，1~8 号分处八段，种子在决赛前都碰不上。这跟文献[2]的分批定位公式效果一样，只是本文用递推生成，不用查表。
　　第三步是填非种子选手，同时避开同单位冲突。非种子先打乱一次，再按所属单位人数从多到少排，人数多的单位限制最强，所以先安排；每放一个人，都算一下他放进各个空位的代价，挑最小的放；代价相同就用蓄水池抽样等概率选一个，既满足约束又保住随机性。代价指的是他跟已落位的同单位选手最早可能在哪一轮碰面，相遇越早代价越大。
　　第四步是查死签，查到就修正。首轮如果还是同单位两个人对上，也就是文献[3]说的死签，算法就建一张冲突图，顶点是选手，边的权值是两人最早可能在哪一轮碰面；然后在图上跑局部搜索，做法是“最陡下降加随机扰动重启”，每轮找能下降最多的那次换位，只允许在非种子之间换，种子位置一律不动；找不到下降方向就随机扰动几下重新起步，最多重启八次。搜索目标是全表同单位配对的加权相遇轮次之和，压到零死签就没了。

2.2　对阵树构建与晋级
　　抽签给出的是首轮配对顺序，相邻两人就是首轮对手；对阵树按逐轮配对展开，也不预置 2 的整数次幂张签位。每一轮把剩下的人两两配对，人数是奇数时有一人轮空直接进下一轮，轮空名额给落位最靠前的那位，而且不让同一个人连着两轮轮空。人数为偶数时首轮没有轮空，真实对局数始终等于参赛人数减一；轮次名称按距离决赛还有几轮来定，十个人参赛首轮已经是 1/8 决赛。每场都记下胜方要去哪一场、站哪个位置，比分记完由指针自动送过去。季军赛可选，只有两场半决赛都是真打时才生成，因为某一侧半决赛如果是轮空轮，那一侧没有负方。

2.3　单循环编排与排名
　　单循环赛要求每两名选手正好打一场，这套算法也用来排小组赛的内部赛程。算法用经典轮转法生成赛程，先把第一个位置固定住，其余位置轮着转，每转一轮就得到一组对阵；人数是奇数时先补一个虚拟轮空位，这样每轮都有一个人轮空，人数是偶数时总轮数等于人数减一，是奇数时就等于人数，每个人实际打满人数减一场。为让赛程均匀些，算法在奇数轮会把对阵双方次序换一下。积分排名依次比积分、净胜局、净胜分和相互胜负关系，还分不出来就按选手编号顺序排；赢一场积 2 分。

2.4　小组循环结合交叉淘汰
　　这种赛制分三个阶段做。第一阶段是蛇形分组，选手按顺位蛇形分到各组，走到最后一组就掉头往回分，来回走下来各组实力能尽量拉平，不会出现“死亡之组”；分完还会做一次组内修正，把同单位的人从同一组换出去。第二阶段是组内单循环，复用 2.3 节那套轮转算法排出组内名次。第三阶段是组间交叉淘汰，落位看人数：人数正好是 2 的整数次幂时，把各组按名次排成块再套一遍蛇形落位，同一个组出来的两个人会分到签表两端，最早只能在决赛碰面；不是 2 的整数次幂时，硬按 2 的幂铺签位会撑出一堆空签，所以改成“名次层交错”，先排各组第一名再排各组第二名，相邻配对的两个人天然来自不同小组，十个人就是实打实的五场。
　　交叉淘汰的首轮还要再做一次冲突修正，这一次不能套用 2.1 节那种通用换位，因为通用换位会把排好的分组结构打乱。所以算法另外写了一套专用修复：同组两个人首轮不能相遇，这是硬条件；同单位相遇则看赛事有没有打开规避开关。换位时要求新旧两个配对都干净，冲突只会一点点变少。要是还有消不掉的，就保留方案并写进抽签留痕，交给组织者人工处理。淘汰赛还要等小组赛全部打完才能生成。

2.5　公平性度量
　　抽签做完以后，系统还会算一份公平性报告。报告给出 0 到 100 的综合得分，由四项加权：种子在各分区分布是否均衡占 35 分，各分区实力总分标准差是否够小占 30 分，同单位规避达成率占 25 分，轮空在上下半区是否均衡占 10 分。另外还会列出各分区种子数、上下半区轮空数、同单位总配对数、首轮同单位相遇对数，并给出风险提示，比如某个单位报名的人超过分区上限因而没法完全避开。分组赛制另有各组人数、种子数、组间实力差等指标。

3　系统实现与测试

3.1　功能实现
　　系统面向使用者提供单淘汰和小组循环结合交叉淘汰两种赛制，单循环的编排与排名算法在小组赛内部使用，也能承担单循环赛事；男单、女单、男双、女双、混双五个项目分支都支持，一共做了 16 个业务页面和 7 组服务端接口。前端把图标、区块卡片、指标卡、标签和空状态五个通用组件抽出来反复使用；网络请求统一从一个模块出口走，鉴权、响应解析、登录态失效处理都在那里做完，接口地址还会按设备信息自动切换。记分支持一局定胜负和三局两胜，可以逐局录入、判定弃权，已录完的场次也能更正；成绩报告给出参赛人数、单位分布、场次完成情况和获奖名单等指标。

3.2　智能名单导入
　　真正办比赛时，名单大多是 Excel 表格交上来的，各院系格式不统一；列顺序不固定，表头有好几种写法，性别和单位写法也不一样，还有的把一对双打组合写在同一格里。解析链路是：先把表格或粘贴的文本变成二维数据，认出表头映射到系统字段，再由规则解析器完成归并和校验，这一步是兜底手段，永远都能用；要是规则解析认不出某列是什么意思，就调用装在本机上的大语言模型判断列语义，这一步属于可选加强，模型没启动、响应超时或输出解析不出来，一律退回规则解析的结果，导入主流程不会被卡住。规则解析本身也做手机号、学号、姓名和单位名的格式判断，还会把写在一格里的双打组合拆开。

3.3　测试与结果
　　服务端接口做过完整的整体测试，从注册登录、选手增删改查、赛事创建和状态流转，到抽签执行和留痕、记分与晋级、统计报告，整条链路都覆盖到了，各种边界场景也重点验过，结果见表 2。

　　测试还验证了同单位规避确实管用；在特意构造的一份同单位人数比较多的数据里，算法能靠在非种子区间换位，把同单位选手第一轮相遇的可能性降到零；要是约束本身满足不了，系统会把冲突明确记下来，而不是悄悄失败。抽签留痕把每一步种子落位、非种子填充和冲突修正之后的顺序都存了下来，结果可以完整复核。实测下来，一百多人的名单，几秒钟就能返回结果，比人工排表快得多。

4　结论
　　本文针对高校羽毛球赛事人工编排的难题，设计和实现了一套智能抽签与编排系统。主要做了三件事；第一，把竞赛规则中种子定位、同单位回避这些约束整理成计算机能处理的条件，提出用蛇形落位把种子分匀、再用冲突图配合局部搜索换位消除死签的抽签算法，换位只在非种子之间做，种子优先原则不会被破坏；第二，把对阵树生成、单循环轮转编排和小组交叉淘汰三套算法统一实现出来，对阵表改用逐轮配对，轮空只出现在某轮人数为奇数时，真实对局数始终等于人数减一；第三，把算法层和业务层彻底分开，所有赛制算法都能单独测试，并额外输出一份公平性报告，让结果好复核。
　　系统已经通过了完整的整体测试，满签、非满签、轮空、弃权和名次派生都能正确处理，编排过程也留了痕，可以复现。以后还可以从三个方面接着做；一是把团体赛支持起来，用一个场次集合去装多场单项赛，做聚合计分；二是加上实时推送，多块场地同时记分时比分也能同步；三是拿往年赛事数据动态修正选手的水平分，让种子评定更准一些。
